# GodGram C# + PostgreSQL

Это **частичный перенос** большого `gg.py` (5946 строк) на ASP.NET Core/C# и PostgreSQL. Старый интерфейс перенесён **без переписывания**: HTML отдельно, CSS отдельно, JavaScript по функциональным разделам. **Файла `index.html` нет.** Главный адрес — `/app` (и перенаправление с `/`).

## Что готово

- **C#:** сервер ASP.NET Core 8, сессии, коды входа для локальной разработки, регистрация, облачный пароль, профили, поиск пользователей, личные чаты, группы, каналы, избранное, сообщения, read-счётчики, закрепление чатов, long-poll обновления.
- **PostgreSQL:** самостоятельная схема нормализованных таблиц `users`, `sessions`, `chats`, `members`, `messages`, `gifts`, `nft_colls`, `nft_items`, `reports`, `stories`, `pins`, `media`, `star_checks`, `bot_updates` и др.
- **JavaScript/CSS:** исходный фронтенд из `gg.py` вынесен в `wwwroot/js/{core,auth,chats,profiles,admin,collectibles,settings}.js` (суммарно около 160 КБ) и `wwwroot/styles.css` (35 КБ); HTML-шаблон — `wwwroot/app.html`. Ничего не открывается через `index`.
- Чтение каталога подарков, коллекций и кошелька, истории с текстом, жалобы, ограниченное чтение панели администратора.

## Не готово (важно)

Сложные функции старого Python (торговля и передача NFT, начисления звёзд, платежи, полноценные боты, голосовые/файлы, фото-истории, множество OWNER-действий) **не перенесены**. API отвечает `501`, а не делает вид, что запрос прошёл. Полное соответствие всем 100+ API старого сервера не заявляется. Исходная база `tgsite.db` **не была предоставлена**, существующие реальные записи в новой БД не импортировались.

> Встроенные коллекции GodGram — **внутренние демонстрационные** коллекции, не проверенные владения реальными Telegram NFT.

## Запуск Windows 10/11

1. Установи [**.NET 8 SDK**](https://dotnet.microsoft.com/download/dotnet/8.0).
2. Установи **Docker Desktop** и запусти его, **или** отдельно установи PostgreSQL 15+.
3. Если используешь Docker: `docker compose up -d db`.
4. Запусти `setup.bat` для восстановления NuGet-пакетов, затем `start.bat`.
5. Открой **http://127.0.0.1:8080/app**.

Docker запускает PostgreSQL в отдельном volume; данные переживают перезапуск приложения. Пароль в docker-compose — **только для локального теста**; перед открытием проекта в интернет обязательно замени его и настрой `GODGRAM_DB`.

Для собственного PostgreSQL установи `GODGRAM_DB` в переменных окружения. Пример смотри `.env.example` (этот файл не подхватывается автоматически).

### Первый администратор

В терминале перед запуском укажи **свой** основной номер (только цифры):

```cmd
set GODGRAM_OWNER_PHONE=998901234567
start.bat
```

Первый случайно зарегистрировавшийся пользователь **не** становится владельцем. Админ выдаётся только номеру, указанному в `GODGRAM_OWNER_PHONE` в момент регистрации. На публичном сервере это необходимо заменить полноценной защищённой процедурой назначения владельца.

### Важно о кодах входа

Сейчас есть **только режим локальной разработки** (`GODGRAM_DEV_CODES=1`): 5-значный код показывается на экране и печатается в терминале. Настоящие SMS не отправляются. **Никогда не включай этот режим на общедоступном сервере.** Для продакшена нужен внешний проверенный провайдер и ограничения попыток, отдельный HTTPS и усиление управления сессиями.

## Проверки

Для фронтенда можно проверить синтаксис: `for %f in (wwwroot\js\*.js) do node --check %f`. Для C# при наличии .NET SDK: `dotnet build GodGram.csproj`. Запуск с PostgreSQL, компиляция C# и полное E2E-тестирование в среде сборки архива **не выполнялись**, так как там нет .NET SDK и PostgreSQL.

## Сборка через GitHub Actions

Этот вариант включает `.github/workflows/build.yml` и создаёт два скачиваемых артефакта:
`GodGram-Windows-x64` (с `.exe` и `run-built.bat`) и `GodGram-Linux-x64`.

Загрузи **содержимое этой папки в корень GitHub-репозитория**, открой
**Actions → Build GodGram (.NET 8) → Run workflow**, затем скачай архив
в разделе **Artifacts** успешного запуска.

Workflow выполняет `dotnet restore`, `dotnet build`, публикацию автономных сборок
и smoke-test Linux-приложения с временным PostgreSQL 16. Постоянная база данных
для использования на компьютере должна быть запущена отдельно.
Подробности — `BUILD-INSTRUCTIONS.md`.
